## Exercise 2 — Build the Service with Bob

With the TTM Forecasting mode active, send Bob this prompt:

```
I need to build a cold-chain temperature forecast service for a fleet management platform.
The service should predict temperature breach risk for pharmaceutical cargo trucks using
IBM Granite TTM-R2. It will connect to the fleet backend at http://localhost:8085 to get
truck telemetry. The critical temperature threshold is 8.0°C. I need the following endpoints:

  GET /api/forecast/temperature/{truck_id}  — predict breach risk over 24 hours
  GET /api/forecast/weather/{truck_id}      — weather impact forecast
  GET /api/forecast/fleet                   — fleet-wide risk summary

Build the complete service in a folder called forecast-backend/.
```

Bob will ask 2–3 discovery questions. Answer as follows:

| Bob's question | Your answer |
|---|---|
| Data source? | Fetch truck telemetry from `http://localhost:8085/api/trucks/{truck_id}` and generate synthetic 512-point temperature history from current temperature |
| UI needed? | No — API only. Dashboard is built separately in Lab 4 |
| Model mode? | `USE_TTM_MODEL=False` (mock mode for the lab — no 3 GB download) |

Bob will present a **checklist plan**. Review it and confirm. Bob then generates all files in `forecast-backend/`. Apply all generated files.

## Exercise 3 — Start and Verify

### Step 3.1 — Fill in credentials

Open `forecast-backend/.env` (created by Bob). It should already have the values from `02-forecast-service/.env.example`. Confirm:

```env
FLEETOPS_API_BASE_URL=http://localhost:8085
USE_TTM_MODEL=False
```

### Step 3.2 — Install and start

```bash
cd forecast-backend
python3.12 -m venv venv
source venv/bin/activate     # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 5001 --reload
```

> **`USE_TTM_MODEL=False`** — startup should be under 5 seconds. No model download.  
> If you see a slow pip install (3–5 min for torch/transformers), that is normal on first run.

✅ **Success:** `Uvicorn running on http://127.0.0.1:5001`

### Step 3.3 — Verify the forecast endpoint

Open `http://localhost:5001/docs`. Call `GET /api/forecast/temperature/{truck_id}` with the incident truck ID.

Confirm the response contains:
- `breach_predicted: true`
- `risk_level: CRITICAL` or `HIGH`
- `recommendations`: list of action strings

### Step 3.4 — Verify the fleet summary

Call `GET /api/forecast/fleet`. Confirm the incident truck appears in `trucks_at_risk`.

### Step 3.5 — Debug with Bob (if needed)

If any endpoint returns an error, ask Bob (still in TTM mode):

```
The forecast endpoint for [truck_id] is not returning breach_predicted.
Help me debug this.
```

Bob will read the generated files and fix the issue.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Slow startup even with `USE_TTM_MODEL=False` | pip is installing torch — wait 3–5 min on first run only |
| `breach_predicted` missing from response | Ask Bob: *"The field breach_predicted is missing — fix the response model"* |
| Connection refused to port 5001 | Confirm the service started and check the terminal for errors |
| Bob generates wrong endpoint paths | Re-send the prompt with explicit paths from Exercise 2 |
